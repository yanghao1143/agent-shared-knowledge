## Browser (Chromium) Configuration

### Snap Chromium AppArmor Issue
- **Root cause**: `Failed to create /home/oldking/.openclaw/browser/openclaw/SingletonLock: Permission denied (13)`
- Snap AppArmor blocks access to `~/.openclaw/browser/`
- `~/snap/chromium/common/` path works for snap-sandboxed Chromium

### OpenClaw Browser Schema (checked)
Only supports: `enabled`, `evaluateEnabled`, `cdpUrl`, `remoteCdpTimeoutMs`, `remoteCdpHandshakeTimeoutMs`, `color`, `executablePath`, `headless`, `noSandbox`, `attachOnly`, `defaultProfile`, `snapshotDefaults`, `profiles`
- **NO `userDataDir` support** - consider filing feature request

### Solutions Deployed
| Machine | Solution |
|---------|----------|
| 1号员工 | `/usr/bin/chromium-browser` (apt version) |
| 2号员工 | CDP workaround: manual start + `cdpUrl: "http://127.0.0.1:18800"` |

### CDP Workaround Command
```bash
/usr/bin/chromium-browser --headless --no-sandbox --disable-gpu \
  --remote-debugging-port=18800 \
  --user-data-dir=$HOME/snap/chromium/common/openclaw-browser &
```

## Key Learnings

1. **Preserve error scenes before /new** - logging blind spot means we lose context
2. **noSandbox config works** - verified in OpenClaw source code, passes `--no-sandbox` and `--disable-setuid-sandbox`
3. **Snap vs apt Chromium** - snap version has strict AppArmor path restrictions
